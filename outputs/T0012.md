## 1. Shift+Enter no longer numbers or bullets lists
- In the chat box, **Shift+Enter now always gives a plain new line**. This holds after `1. one`, `- item`, `- [ ] task` or `3) third`. Nothing is added to the next line.
- **Enter still sends.** Enter doesn't send while a character is still being composed in an input method (IME), such as Japanese.
- I removed the list feature completely: the code (`web/lib/listContinue.mjs`), its tests and the "Auto lists: on/off" switch under the chat box.
- Your browser may have saved "on" from the first version of this pull request. That setting is now ignored and deleted when the page loads, so it can't turn the feature back on.
- The key handling now lives in `web/lib/composerKeys.mjs`. Only the send keypress is blocked. Shift+Enter is left to the browser.
- New tests replace the ones that checked for numbering:
  - `web/tests/composerKeys.test.mjs` checks for a plain new line after numbered, bulleted and checkbox items and after empty items. It also checks that Enter sends and that the Enter that finishes an IME character neither sends nor is blocked.
  - `tests/test_web_ui.py` checks that the key handler blocks only the send keypress and that none of the old list code or saved setting is left.

## 2. The "Get a key ↗" link now works from the keyboard
- On the Models page, the provider cards (Groq, Gemini, …) under "Which API?" were the problem. The link sat inside a clickable card, and the card cancelled Enter.
- Now each card has a real button that picks the provider, and the "Get a key" link sits beside that button, not inside it. The card handler is gone.
- Enter on the focused link opens the key page in a new tab and leaves the selected provider unchanged.
- Space or Enter on a provider's button picks it. Tab moves from a provider to its link.
- The cards look the same as before; I checked a screenshot of the add section.
