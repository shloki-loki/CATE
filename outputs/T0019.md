# T0019: Skeleton codebase setup — done

**Pull request: https://github.com/shloki-loki/CATE/pull/6** (branch `cate/T0019-game-skeleton`, targets `main`; the owner reviews and merges)

## What was built
A runnable skeleton for **Neon Coast**, the original browser driving game, in a new top-level `game/` directory with its own `package.json`. It uses the engine chosen in T0017: Three.js with WebGL2, plus Rapier physics, Vite and strict TypeScript. It follows the approved architecture (T0016 §4).

**Branch deviation (deliberate):** the brief said to create a branch called `browser-gta`. The approved architecture (T0016 §1/§6) and rule 7 call for `game/` on a `cate/T0019-*` branch through a pull request instead, because a long-lived side branch would never be reviewed or merged.

- **package.json and engine:**
  - Pinned `three` 0.187.0 and `@dimforge/rapier3d-compat` 0.21.0.
  - Dev tools: Vite 8.4, TypeScript 6.0.3 (TS 7 is not yet supported by typescript-eslint), Vitest 5, Playwright 1.65, ESLint 10, Prettier.
  - Lockfile committed.
- **Folder layout:**
  - `game/src/` contains `core`, `input`, `physics/rapier`, `render`, `audio`, `assets`, `ui`, and `game/{components.ts, events.ts, shared, camera, demo, world, player, vehicles, ai, combat, wanted, missions, save}`.
  - `game/assets/` holds source assets for the generators (not served).
  - `game/public/` holds served files: `assets/manifest.json`, favicon, `THIRD_PARTY_NOTICES.txt`.
  - Also `game/tools/` and `game/tests/{unit,e2e}`.
- **Engine core:**
  - Fixed 60 Hz loop with render interpolation.
  - ECS world that runs systems in order.
  - Queued, typed event bus.
  - Settings saved to `localStorage`, plus in-game time of day.
- **Contracts for the next tasks:**
  - `PhysicsAPI`/`RapierPhysics`: bodies, transforms, impulses, raycasts, collision groups.
  - `RenderAPI`/`ThreeRenderer`: WebGL2, ACES tone mapping, sRGB, sun shadows, quality presets, resize handling.
  - Also `InputAPI` (actions), `AssetAPI` (manifest registry), `AudioAPI` (silent placeholder), `Services`, and shared component and event types.
- **Minimal scene with camera:**
  - Ground, road grid, beach and sea, 38 placeholder buildings (each with a collider) and palms.
  - 10 crates and a car placeholder that fall and settle using Rapier.
  - Orbit camera (drag, wheel, WASD) with a raycast "spring arm" so it never enters buildings.
  - F3 debug overlay; about 160 draw calls.
  - If WebGL2 is missing, the page shows a clear message.
- **Module boundaries:** `tests/unit/boundaries.test.ts` resolves every import and enforces the T0016 §4.2 rules (Rapier only in `physics/rapier/`, no imports from `ui` into `game`, and so on). It includes self-tests showing it catches violations.

## Problems found and fixed during testing
- The camera's first start position was inside a building, which gave a mostly black image. It now starts above a road, and the spring arm keeps it out of buildings.
- The first version made about 776 draw calls. Merging road dashes and window bands brought it down to about 160.
- three r187 removed `PCFSoftShadowMap` and logged a warning, so it now uses `PCFShadowMap`. A missing favicon caused a 404, so one was added.

## Limits (stated honestly)
- **No CI job runs `game/` checks yet.** Agents cannot edit `.github/workflows/`. The owner could add a job: `cd game && npm ci && npm run check && npx playwright install --with-deps chromium && npm run test:e2e`.
- Only tested headless with software rendering (about 8–24 fps there). No frame rate on real GPUs is claimed.
- Vehicle, character, shape-cast and contact-event physics are left for T0020 and T0021, as planned in the architecture.
- The Rapier chunk is about 4.3 MB minified (about 1.7 MB gzipped) because the WASM is embedded. That is within the 30 MB first-load target.

## Run it locally
`cd game && npm ci && npm run dev`, then open http://localhost:5173. For a static build: `npm run build && npm run preview`.
